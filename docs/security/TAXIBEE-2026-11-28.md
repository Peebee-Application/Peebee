# Taxibee security review — 28 November 2026

**Security work remains open. This review is not a penetration-test certification,
and Taxibee must not be described as unattackable or bank/military-grade.**

Reviewed current `origin/main` at `dddfd298`, rather than the older handover
branch. Scope: Taxibee gateway, authentication/session flows, browser integration,
PWA caching, dependency advisories, and selected shared TaxiPress/payment controls.
No production customer credentials were used, no money was moved, and no
load testing, brute force, or destructive production probes were performed.

## Implemented session controls

- Login/register/auth token responses are translated at the gateway: the actual
  backend credential is only in a host-only Secure, HttpOnly, SameSite=Strict
  cookie. The response/body and local storage carry a non-secret marker.
- Backend authentication is still mandatory. The marker is never forwarded
  as a credential; it cannot authenticate without the cookie.
- Cookie-authenticated writes require an exact matching Origin, including
  rejection of sibling-subdomain requests. SameSite alone is insufficient.
- Logout and expired-cookie responses remove the cookie. Legacy browser
  bearer sessions migrate only after the backend accepts `/auth/me`.
- The existing upstream user/role/ownership/revocation checks remain authoritative.
- API responses remain `no-store`. Ordinary upstream cookies are dropped.
- Redirect non-local HTTP requests to HTTPS before processing them, and add
  HSTS for HTTPS responses without including unrelated subdomains.
- Updated PWA shell cache version so the new browser adapter is fetched.
- Disabled Taxibee's public `workers.dev` alias in deployment configuration.

These changes affect Taxibee sessions only, not the other Peebee apps' token
storage. Session cookies still depend on TLS, backend credential validation,
and the user's device. Logout revocation requires a working network.

## Verified checks

- Taxibee production build and TypeScript check passed.
- Gateway tests cover token redaction, cookie flags, marker substitution,
  origin rejection, logout, migration, upstream restriction, cache/cookie
  isolation, upstream errors, scoped support capabilities and client identity.
- A real Chromium test through the gateway confirms `document.cookie` cannot
  read the credential, the browser receives only the marker, authenticated
  requests reach the upstream fixture, and logout removes access.
- **32 shared API tests passed**, including booking ownership/isolation,
  queue and payment rules, settlement, payment reconciliation and ticket sharing.
- The full shared API suite with patched Hono passed **1,203 tests**, with no failures, cancellations or skips. Subsequent tooling-only dependency overrides do not change Hono/API runtime versions.
- Shared API TypeScript build passed.
- **15 Taxibee unit tests passed**, plus the real-browser cookie/session test.
  Session markers are bound to the cookie credential and change with the
  authenticated session; stale markers cannot authorize writes in a newer session.
- The full existing browser run passed the main customer/authentication,
  seat allocation, standard/corporate return, parcel/charter and travel-credit
  suites. The final account-tools suite timed out waiting for P2P audio to
  connect. Repeating that suite with the unchanged `origin/main` adapter
  reproduced the same connection timeout. It is not introduced by the session
  change; its underlying cause is not established. Do not report the entire
  browser suite as passed or claim live calls were verified here.
- A narrow secret-signature scan of **2,581 tracked text files** found no
  GitHub credential, AWS access-key-ID or private-key-block matches. This is
  not a complete secrets/history audit and does not detect all secret formats.
- Registry production audit: before **13 moderate + 1 low**; after API patches
  **7 moderate**, all remaining production findings attributed to Next.js.
- Full registry audit after API patches: **1 critical + 13 high + 20 moderate**.
  After the scoped tooling overrides: **0 critical + 9 high + 16 moderate**.
  These counts include development/tooling dependencies; production-only scans omit them.
  A `devDependency` label does not prove a package is excluded from deployed
  artifacts; OpenNext bundle/runtime reachability still requires validation.
- Existing application browser suites are run separately and their outcome is
  recorded in the PR; fixture success does not establish real payment settlement.

## What could not be established

Read-only HTTPS probes to the public Taxibee URL returned 403 responses with
an Envoy server header from this execution environment. They do not establish
the deployed app's headers or security controls; the response must not be
reported as a missing CSP/HSTS finding on the real app.

This is a bounded source/dependency/targeted-regression review. It does not
cover every Peebee API endpoint, malicious-provider behaviour, compromised
staff accounts, recovery procedures, physical-device threats or all race
conditions. No independent penetration test, ASVS conformance review or
payment-industry certification was performed.

   multi-account isolation, payment failure/retry and logout on staging.
4. Complete dependency remediation, strict CSP/DOM work and an independent,
   authorized authenticated penetration test before any stronger security claim.
5. Verify production monitoring, edge abuse controls, privileged MFA, backups,
   restore drills and secret rotation. Keep dependency scanning continuous.
